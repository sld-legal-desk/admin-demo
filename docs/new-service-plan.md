# 新サービス事業計画 ― 専門書店「業務OS」(①) × 内製化伴走 (③) 二段構え

> 作成日: 2026-06-29 / 対象: 金子 諒
> 意思決定シート（①〜③比較）の結論「**③で食べながら①を育て、②で大きくする**」を実行計画に落とし込んだもの。

---

## 0. エグゼクティブサマリー

- **本命は①**（専門書店向け業務OS SaaS）。至誠堂向けに構築済みの管理ダッシュボードを汎用プロダクト化する。参入障壁・強み適合・スケール余地が最も高い。
- ①の弱点は「初期投資」と「回収速度」、そして「至誠堂1社依存」。これを**③（内製化の伴走＋構築）で補完**する。③は即現金・即顧客接点・①の見込み顧客リストを同時に生む。
- ②（電子書籍／機関配信）は版権・資本・大手競合の壁が大きいため**将来オプション**として温存。①で取引データが貯まってから展開する。
- 戦略を一言で：**単独・低リスクで③を始め、勝ち筋（①）に資源を寄せ、②で大きくする。**

```
   現金・顧客 ──▶ ③ 内製化伴走 ──┐
                                 ├─▶ ① 業務OS SaaS ──▶ ② 電子書籍/機関配信
   R&D費の肩代わり ─────────────┘     (本命・資産)         (将来の拡張)
```

## 1. フェーズ0–1：③ 内製化伴走サービス（即収益エンジン）

「事業企画ひとりが業務を構造化し、ダッシュボード／ECとしてシステム化する」というあなた自身の実績を商品化する。コンサルで終わらず**実装まで一人で完結できる**点が希少価値。

### 1-1. サービスメニュー（3階層）

| プラン | 内容 | 価格（目安） | 狙い |
|---|---|---|---|
| **業務棚卸し診断** | 業務フローのヒアリング→構造化図→システム化ロードマップ（2週間） | 30〜50万円 | 入口商品・①の見込み発掘 |
| **内製化伴走（顧問）** | 月次で業務設計＋ローコード／ダッシュボード構築の伴走 | 月20〜40万円 | 継続収益の柱 |
| **個別構築** | 受発注・在庫・EC・分析ダッシュボードの設計〜実装 | 100〜300万円/件 | スポット大型 |

> 価格は「①のR&D費を賄える水準」で設定。診断→顧問→構築の順で単価を上げる。

### 1-2. ターゲット（最初の10社の選び方）

「至誠堂と業務構造が近い＝①の見込み顧客でもある」企業を優先。

- 医学書・専門書・学術書を扱う**中小書店／専門書店**
- **大学生協・大学購買部**、専門学校の購買
- **出版社の直販・通販部門**（受発注と在庫を自前で持つ規模）
- 専門商社・卸（委託／返品の商習慣を持つ業種＝①の機能が刺さる）

### 1-3. 立ち上げアクション
1. サービス紹介1枚（上記メニュー＋至誠堂の事例＝ビフォーアフター）を作る
2. 既存の業界つながり（出版社・取次・同業）から**診断プラン**を3社に打診
3. 診断の納品物（構造化図・ロードマップ）をそのまま①の要件定義インプットに再利用

## 2. フェーズ1–2：① 専門書店「業務OS」SaaS（本命・資産）

### 2-1. プロダクトの定義
専門書流通に特化した一気通貫の業務SaaS。汎用ERP／POSが噛み合わない**専門書ならではの商習慣**（委託・返品・出版社別レポート・電子書籍配信）を標準実装することが差別化の核。

既存ダッシュボードが持つ機能（資産）：
- 受発注・ピッキング・佐川連携（OrdersView）
- 在庫管理・入荷待ち・電子化リクエスト
- 会員CRM・メール配信
- 書籍EC・デジタル商品／電子書籍配信
- 売上／粗利分析・消し込み（入金消込）
- 出版社レポート・バナー／メール広告枠

### 2-2. MVP範囲（最初に売れる最小単位）
全部入りを売らない。**「受発注＋在庫＋出版社レポート」**をコア機能として切り出し、まず2社目を獲得する。

- コア：受発注 / 在庫 / 出版社別売上レポート / 基本の売上分析
- 後続：電子書籍配信、広告枠、消し込み、CRM（顧客要望が出た順に有料アドオン化）

### 2-3. 既存ダッシュボードのSaaS化リファクタ計画
現状は単一 1.3MB の `dashboard.jsx` をブラウザ内 Babel で実行する構成。マルチテナントSaaSにするには下記が必要（コード内 `TODO[P0]` のファイル分割計画と整合）。

1. **ビルド基盤整備**：Vite 化、CDN実行をやめてバンドル。
2. **コンポーネント分割**：`TODO[P0]` 通り OrdersView 等を分割し再利用可能に。
3. **バックエンド／DB**：マルチテナント対応のデータモデル（テナントID分離）。※スタックに Supabase が接続済み → 認証・DB・行レベルセキュリティ(RLS)でテナント分離を実装しやすい。
4. **認証・権限**：店舗／出版社／管理者のロール分離。
5. **課金**：Stripe でプラン課金（下記モデル）。
6. **オンボーディング**：商品マスタ・出版社マスタの取込（CSV/API）。

### 2-4. 課金モデル
- **月額サブスク**（店舗規模＝注文件数のレンジで段階課金）
- **アドオン**（電子書籍配信／広告枠／消し込み等を機能単位で）
- 初期費用（データ移行・初期設定）をスポットで

### 2-5. ターゲット
③で接点を持った企業のうち、共通課題が確認できた先から2〜3社目を獲得 → 横展開。
